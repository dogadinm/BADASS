# Проверка проекта — 2026-10-11

## Окружение

macOS / Apple Silicon, Docker Desktop, образы устройств **linux/amd64**
через эмуляцию. GNS3 Server **2.2.55**, uBridge **0.9.19**, Dynamips **0.2.23**.
FRR в сдаваемом образе: **10.5.3**.

GNS3 запущен в отдельной Linux-лаборатории с собственным вложенным Docker
Engine 26.1.5. Лаборатория не использует Docker-сокет или PID namespace хоста.
Устройства P2/P3 — отдельные настоящие контейнеры GNS3 с UDP-соединениями,
а не только network namespaces. Команды проверки выполнялись через
Auxiliary Telnet consoles. GUI GNS3 не использовался.

- `sh P2/scripts/check.sh`: **PASS**, exit 0. Проверены инструменты хоста,
  службы/конфигурация FRR, отсутствие IP по умолчанию, перезапуск P1,
  оба режима P2, повторное применение скриптов, MTU, MAC/FDB, захват
  multicast/VXLAN и отказ при отключённом туннеле.
- `python3 scripts/check-gns3.py --export-dir /tmp/verified-exports`:
  **PASS**, exit 0. Импортированы P2 static, P2 multicast и P3; после проверок
  выполнены реальные portable exports через GNS3 API. Docker-образы включены.
- Для каждого проекта: ping между всеми парами хостов с IPv4-пакетом 1450
  байт без фрагментации, удалённые MAC в FDB, VNI 10 в захвате, потеря связи
  при выключении туннеля и восстановление после включения.
- P2 multicast: членство в `239.1.1.1` и пакеты к multicast-группе в захвате.
- P3: OSPF-соседства, доступность loopback всех leaf, три динамических

- P3 после удаления IP хостов и отправки ARP probes: MAC/type 2 появляются

- Stop all → Start all: **PASS** для всех трёх проектов; адреса, мосты,
  VXLAN и FRR восстанавливаются автоматически.
- ZIP CRC, отсутствие дубликатов, совпадение `.gns3` с `project.gns3`
  внутри архивов, соответствие упакованных конфигураций исходникам:
  **PASS**. Архитектура проверена внутри Docker image tar: linux/amd64.
- Синтаксис shell/Python и `git diff --check`: **PASS**.

`python3 scripts/check-gns3.py` на итоговых экспортированных архивах:
**PASS**, exit 0. Все три архива повторно импортированы как новые проекты;
весь набор проверок, включая Stop/Start, прошёл повторно.

## Что исправлено при проверке

GNS3 определяет заполненность Docker volume по `.gns3_perms`. Без этого
файла он копирует в том конфигурацию базового образа при первом старте.
Генератор теперь включает этот маркер и права FRR: конфигурации P3 не
заменяются конфигурацией P1. Этот случай обнаружен реальным импортом GNS3.

Постоянные сетевые настройки P2/P3 находятся в `/etc/network/lab.sh` и
запускаются из `/etc/network/start.sh`, поэтому повторять команды после
перезапуска не требуется. Базовые образы P1 не изменены.
