# Проверка P1

Дата: 2026-09-12.

## Проверенное окружение

- Mac с Apple Silicon, Docker Desktop 4.60.1 / Docker Engine 29.2.0.
- Оба образа собраны для `linux/amd64` и запущены через эмуляцию.
- Alpine 3.23, FRRouting 10.5.3-r1.
- GNS3 Server 2.2.55 с uBridge 0.9.19 во временном Linux-контейнере
  внутри Linux-VM Docker Desktop. GUI GNS3 не использовался.

## Успешные проверки

1. Сборка обоих Docker-образов из исходников.
2. Наличие BusyBox, iproute2, ping и tcpdump в хосте; ping loopback.
3. Живые процессы и доступные VTY-сокеты mgmtd, zebra, bgpd, ospfd,
   isisd и staticd.
4. В рабочей конфигурации есть BGP AS 65000, OSPF и IS-IS P1.
5. Нет назначенных глобальных IP-адресов.
6. `docker restart`: службы и конфигурация восстанавливаются.
7. Создание проекта через API GNS3, запуск обоих устройств.
8. Выполнение проверок через обе вспомогательные Telnet-консоли GNS3.
9. Реальный portable export GNS3 и добавление обоих Docker-образов.
10. Проверка целостности ZIP и загрузка образов через `load-images.py`.
11. Удаление исходного тестового проекта, импорт сдаваемого архива как
    нового проекта, запуск обоих устройств и проверки через Telnet.
12. Остановка и повторный запуск импортированного проекта в GNS3;
    проверки консолей и служб снова прошли.
13. Синтаксическая проверка shell- и Python-скриптов.

Тест перезапуска обнаружил и помог исправить проблему оставшихся PID-файлов:
entrypoint удаляет только временные данные FRR внутри контейнера, сохраняя
`/etc/frr`. Вспомогательная консоль GNS3 использует собственный BusyBox;
для полного iproute2 в README указан переход `exec /bin/sh`.

## Что остаётся проверить в школе

Школьный Intel/Linux-компьютер и установленный там GUI сейчас недоступны.
В Linux-виртуалке загрузить образы из архива, импортировать проект через GUI,
открыть Auxiliary console обоих устройств и повторить команды из README.
Это финальная проверка целевого окружения перед защитой.
